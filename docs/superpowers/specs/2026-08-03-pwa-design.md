# PWA Offline-First Design (manifest + service worker + update prompt)

Date: 2026-08-03

## Objective

Convert Ibadah Quest (vanilla JS/HTML/CSS, no build tools, localStorage state) into an
installable Offline-First PWA: `manifest.json` for standalone install, a versioned
Service Worker that pre-caches the app shell and serves dynamic scripts via
Stale-While-Revalidate, and a registration block that detects pending updates and
prompts the user to refresh. Robust against caching bugs and stuck updates.

## Context

- The app is served over HTTPS (GitHub Pages), so Service Worker + install are available.
- `index.html` eagerly loads ~60 same-origin scripts, many with `?v=` cache-buster
  query strings (`data/*.js?v=3`, `render/render.js?v=2`, `features/*.js?v=1`, ...).
- Three pools are lazy-loaded on demand: `data/pools/quran-verses.js?v=3`,
  `data/pools/hadiths.js?v=3`, `data/hadith-collections.js?v=1`.
- Cross-origin requests: chart.js from `cdn.jsdelivr.net` (eager, analytics only) and
  prayer times from `api.aladhan.com` (runtime fetch with try/catch + localStorage cache).
- `toast()` is a private closure in `core/actions.js` (not on `window`); the update
  prompt therefore uses its own self-contained inline banner.
- No icon assets exist in the repo; icons are generated programmatically.

## Design decisions

1. **Cache versioning:** single `CACHE_NAME = 'iq-cache-v1'` constant in `sw.js`.
   Bumping it is the breaking-change lever; `activate` purges all other `iq-cache-*`
   caches automatically.
2. **Stale-While-Revalidate** for all same-origin GET requests. Serve the cached copy
   instantly, refresh it from the network in the background, and on network failure
   fall back to the cache. Content updates flow naturally on every page load.
3. **Cache key = pathname, query stripped** (`https://host/data/deeds.js?v=3` →
   `/data/deeds.js`). This makes the existing `?v=` bump system compatible: new
   versions overwrite the same cache slot instead of leaking old entries.
4. **Pre-cache only the app shell** (`/`, `index.html`, `styles/main.css`) at install.
   Every other script is cached on first visit via SWR — no need to pre-cache the
   full ~60-file list, and first install stays fast.
5. **No `skipWaiting()`** on install. Updates land in a "waiting" state so the page
   can prompt; the user triggers activation with a `SKIP_WAITING` postMessage.
6. **Cross-origin requests are never cached** (pure pass-through) — avoids opaque
   response bugs and stale API data. Known tradeoff: analytics charts (chart.js CDN)
   need a network connection; prayer times already degrade gracefully.
7. **Update prompt:** inline fixed-bottom banner, shown when a new Service Worker is
   waiting, with a Refresh button. Banner uses inline styles (no CSS dependency).

## Files

### `manifest.json` (new, repo root)

- `name: "Ibadah Quest"`, `short_name: "IbadahQuest"`, `lang: "en"`
- `start_url: "./"`, `scope: "./"`, `display: "standalone"`
- `background_color: "#0b1114"`, `theme_color: "#0b1114"`
- `icons:` `icons/icon-192.png` (192×192, purpose `any`), `icons/icon-512.png`
  (512×512, purpose `any`), `icons/icon-maskable-512.png` (512×512, purpose `maskable`)

### `icons/` (new)

Three PNGs generated by a one-off PowerShell script (System.Drawing):
dark-green rounded square background (gradient `#0d1a14` → `#14532d`), gold
(`#D4AF37`) crescent + five-point star in the center. Maskable variant: full-bleed
background with the glyph confined to the center 80% safe zone.

### `sw.js` (new, repo root)

Structure: an IIFE containing pure helper functions, then event wiring guarded by
`typeof self !== 'undefined' && self.addEventListener`.

- `CACHE_NAME = 'iq-cache-v1'`; `CORE = ['/', 'index.html', 'styles/main.css']`
- Pure helpers (testable in node:vm with a fake `self`):
  - `cacheKey(urlString)` → `URL` object's pathname only (query/hash stripped)
  - `shouldCache(request)` → GET method && `http:`/`https:` protocol only
  - `isSameOrigin(url)` → origin equals `self.location.origin`
  - `isCoreCache(name)` → name starts with `iq-cache-`
- `install` event: `event.waitUntil(Promise.all(CORE.map(fetch → cache.put(cacheKey))))`.
  Fail-fast: if any core file fails, install fails (no half-broken offline shell).
  No `skipWaiting()`.
- `activate` event: delete every cache whose name `isCoreCache(name)` and
  `name !== CACHE_NAME`, then `clients.claim()`.
- `fetch` event:
  - Skip (return) if `!shouldCache(request)`.
  - Cross-origin (`!isSameOrigin`) → plain `fetch(event.request)`, never cached.
  - Same-origin → SWR:
    1. respond with `caches.match(cacheKey(request.url))` (may be undefined)
    2. `fetch(request)` → on success, `cache.put(cacheKey(request.url), clone)`
    3. return cached if network failed/offline; else the fresh response
    4. navigation requests: if nothing is cached and the network fails, fall back to
       the cached `/` (app shell) so offline navigation never dead-ends
  - Never cache POST/non-GET/opaque/cross-origin responses.
- `message` event: `{type: 'SKIP_WAITING'}` → `self.skipWaiting()`.

### `index.html` changes

- `<head>`: `<link rel="manifest" href="manifest.json">`,
  `<meta name="theme-color" content="#0b1114">`,
  `<link rel="apple-touch-icon" href="icons/icon-192.png">`,
  `<meta name="apple-mobile-web-app-capable" content="yes">`,
  `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`
- End of `<body>`: registration + update-prompt inline script:
  - Register `sw.js` in the `load` event, only if `'serviceWorker' in navigator` and
    the page is a secure context (`window.isSecureContext`).
  - On `reg.updatefound`: if `reg.installing` exists, wait for it to become
    `installed` (or detect `reg.waiting`), then show the banner:
    fixed-bottom, inline-styled, "🔄 New version available" + Refresh button.
  - Refresh: `reg.waiting.postMessage({type: 'SKIP_WAITING'})`, then a one-time
    `navigator.serviceWorker.addEventListener('controllerchange', ...)` that
    `location.reload()`s.
  - If a new SW is already waiting at registration time (`reg.waiting` set), show
    the banner immediately.
  - Banner is removed from the DOM when clicked/reloaded; no localStorage state
    needed (it re-appears per page load until the update is applied).

### Tests

- `tests/html.test.js` — extend: assert manifest link, theme-color meta, and the
  SW registration script block are present in `index.html`.
- `tests/manifest.test.js` (new) — parse `manifest.json`; assert name,
  short_name, display `standalone`, start_url/scope, theme colors, 3 icons with
  correct sizes/purposes; assert the icon files exist on disk (192/512/maskable).
- `tests/sw.test.js` (new) — load `sw.js` in a node:vm with a fake `self`
  (with `location.origin` and an `addEventListener` recorder):
  - `cacheKey` strips `?v=` queries and hashes, keeps pathname
  - `shouldCache` accepts same-origin GET, rejects POST and non-http(s)
  - `isSameOrigin` splits same-origin vs cross-origin
  - `isCoreCache` matches `iq-cache-*` prefix, rejects other names

## Out of scope

- Caching the prayer-times API or chart.js CDN responses
- `skipWaiting`-on-install / auto-reload updates (prompt flow by design)
- iOS install prompt / push notifications / web app manifest niceties beyond the metas above
- Changing the existing `?v=` cache-buster convention

## Acceptance checklist

- [ ] `manifest.json` + 3 icons exist; Lighthouse/PWA installability passes
  (name, theme, standalone, 192/512 icons)
- [ ] First load online: all same-origin scripts land in `iq-cache-v1`
- [ ] Load twice offline (devtools offline or airplane mode): full app renders from
  cache; toggles/state/localStorage work as normal
- [ ] Refresh offline after data was served: stale-while-revalidate serves cache,
  no blank page, no console errors from failed fetches
- [ ] `cacheKey` strips `?v=`: bumping a `?v=3` script to `?v=4` updates the same
  cache slot on next online load (no stale copy served)
- [ ] Bumping `CACHE_NAME` to `iq-cache-v2` purges `v1` from cache storage on activate
- [ ] A new `sw.js` version → banner "🔄 New version available" appears; Refresh
  applies the update and reloads once; banner never shows again for that version
- [ ] No old `iq-cache-*` entries remain after several update cycles
- [ ] `node --test tests/*.test.js` — all existing + new tests pass
